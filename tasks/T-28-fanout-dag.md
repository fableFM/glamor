# T-28 Fan-out подзадач (DAG внутри рана)

Статус: todo · M4 · зависимости: T-20 (редактор), T-03 (движок)

## Цель

Параллельные ветки в пайплайне (из BRAINSTORM: task DAG, fan-out):
например, независимые подзадачи кодинга по разным модулям, затем
join-ревью.

## Дизайн-набросок (уточнить в реализации)

- Рёбра «split»/«join»: нода split декларирует N параллельных веток
  (статически в пайплайне; динамический fan-out по списку от LLM — НЕ
  в первой версии, риск неконтролируемого роста).
- Семантика join: все ветки succeeded → join-этап; любая failed →
  политика (fail fast | wait all).
- Git-конфликт параллельных веток в одном чекауте: ветки работают
  последовательно на уровне git? или разные worktree с мержем? —
  ГЛАВНЫЙ открытый вопрос; учитывая D-30 (без worktree), первый вариант
  fan-out: параллелятся только read-only/исследовательские этапы
  (планирование подзадач, ресёрч), пишущие этапы остаются линейными.
  Зафиксировать в ADR.
- Пул процессов (T-09) уже поддерживает параллелизм.

## Критерий выхода

- ADR + реализация split/join для read-only веток; редактор умеет
  рисовать такие рёбра; движок корректно ждёт join.
