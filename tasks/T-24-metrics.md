# T-24 Метрики: токены и время per stage

Статус: todo · M3 · зависимости: T-06 (usage-события), T-04

## Цель

Учёт стоимости работы (D-51): сколько токенов/времени съел каждый этап,
ран, роль.

## Scope

- Сбор: usage-события стрима → агрегация в `run_stages.tokens_in/out`
  (инкремент в той же транзакции, что и батч событий). Длительность —
  из started/finished_at; время ожидания гейтов считается отдельно
  (gate_wait_seconds — производное из событий, не хранить).
- Отсутствие usage в harness'е (см. capability matrix) → метрики «—»,
  не выдумывать.
- API: `GET /runs/{id}/metrics` (per stage + итог), `GET
  /projects/{id}/metrics?period=` (агрегация по ранам — sqlbuilder).
- UI: таб «Метрики» этапа (T-14, уже заложен), итоги в header рана,
  простая страница статистики проекта (таблица + пара графиков —
  uPlot или аналог лёгкий, без тяжёлых чартов).
- Экспорт CSV рана (кнопка) — для личного учёта.

## Acceptance

- Цифры на экране рана совпадают с суммой usage-событий журнала (тест).
- Ран из 4+ этапов с петлёй: метрики корректно группируются по итерациям.
