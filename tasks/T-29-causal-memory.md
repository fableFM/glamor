# T-29 Причинно-следственная память (Lessons)

Статус: done (2026-08-17) · M3 · зависимости: T-11 (гейты), T-23 (vendor-память, FTS5)

## Цель

После сессий glamor извлекает причинно-следственные связи («почему так
надо»), предлагает пользователю сохранить их в проектную/глобальную память
и использует в следующих ранах. Не «мы пишем код», а «мы учимся на
объяснениях пользователя».

## База исследования (почему такой дизайн)

- Фреймворки памяти (mem0, Zep/Graphiti, Letta, Cognee) — внешняя
  инфраструктура (vector DB / cloud / LLM-на-запись), заточены под
  conversational recall, противоречат локальности/NDA. **Не берём.**
- Релевантная линия — experience-learning агентов: Reflexion (вербальные
  рефлексии), ExpeL (извлечение инсайтов из успехов/провалов), Voyager
  (библиотека навыков), ACE (эволюционирующие playbooks).
- Практические эталоны — Claude Code скиллы: claude-reflect (захват
  коррекций → очередь на human review → маршрутизация в CLAUDE.md/rules),
  autoskill (детект повторяющихся правок пользователя → патчи в скиллы),
  claude-memory-skill (update/prune/status), consolidate (post-session
  извлечение с типизацией: convention/correction/preference...).
- Общий паттерн всех рабочих решений: **извлечение кандидатов → человек
  подтверждает/редактирует → файлы → инъекция в следующие сессии**.
  У нас всё для этого уже есть: журнал событий (полные трейсы), гейты
  (human review UX), двухуровневая файловая память, FTS5, шаблоны промптов.

## Модель данных: карточка урока

```markdown
---
id: lesson-<ulid>
status: proposed | confirmed | superseded
scope: global | project | vendor:<name>
triggers: [список тем/технологий/паттернов для FTS-матчинга]
created: <дата> · run: <run_id> · stage: <stage_key>
applied_count: 0 · last_applied: null · relapse_count: 0
---
# <краткое правило одной строкой>

## Ситуация
<что делали>

## Симптом
<что пошло не так / что поправил пользователь>

## Причина (почему)
<объяснение пользователя / выведенный root cause>

## Правило
Когда <триггер> — <делай X / никогда не Y>.

## Доказательства
<ссылки: ран, этап, файлы, verdict>
```

Хранение: `lessons/*.md` рядом с vendor-памятью, двухуровнево
(`~/.glamor/lessons/` + `<repo>/.glamor/lessons/`), git-версионирование
как в T-23, FTS5-индекс (та же механика).

## Жизненный цикл

1. **Захват сигналов (бесплатно, детерминированно)**: во время рана ядро
   маркирует кандидатов в уроки: ответ пользователя на вопрос планировщика,
   comment на гейте, queue note, fix-итерация по находке ревьюера,
   relapse (reviewer нашёл то же, что находил в прошлых ранах).
2. **Distill-этап (опциональный, дешёвый)**: после завершения рана —
   LLM-этап (low effort) читает маркированные куски журнала и формирует
   черновики карточек. При неясной причине — формулирует **вопрос
   пользователю** («ты попросил не использовать X — почему?»).
3. **Гейт «Сохранить урок?»**: на финальном гейте (или отдельным гейтом)
   показываются черновики: [Сохранить] [Сохранить в глобальную]
   [Редактировать] [Отклонить]. Ответ на вопрос дистиллера дописывается в
   «Причину» — это и есть диалог «ИИ спрашивает — я объясняю».
4. **Инъекция**: при старте этапа релевантные confirmed-уроки (FTS по
   задаче + scope + триггеры, top-K с токен-бюджетом) добавляются в промпт
   секцией «Подтверждённые уроки». Счётчик `applied_count++`.
5. **Петля качества**: если reviewer снова нашёл нарушение правила —
   `relapse_count++`, урок подсвечивается в UI («не работает — уточнить
   формулировку?»). Периодический prune/merge дублей (ручной из UI,
   не авто).

## Принципы

- Уроки — контекст, не команды: ядро ничего не исполняет из уроков.
- Ничто не попадает в память без подтверждения пользователя (proposed ≠
  confirmed). Исключение: relapse-статистика — она факт.
- Токен-бюджет инъекции конфигурируем (дефолт ~2k токенов на этап).

## Acceptance

- Сценарий: пользователь на гейте поправил кодера («у нас не используем
  X, потому что Y») → distill предложил карточку → гейт → сохранена →
  следующий ран с похожей задачей получил урок в промпте (проверить по
  prompt-*.md).
- UI «Память → Уроки»: список, статусы, фильтры по scope, редактирование,
  история.
- Отклонённый урок не предлагается повторно в том же виде (dedup по
  триггерам).
