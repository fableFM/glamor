# AGENTS.md — правила работы над glamor

## Точка входа

1. Прочти `tasks/00-overview.md` — реестр решений D-01…D-80. Это закон.
   Отклонение от решения — только через явную правку overview (с пометкой
   даты и причины), никогда молча в коде.
2. Найди свою таску `tasks/T-NN-*.md`. Scope (in/out) и Acceptance в ней —
   контракт. Не выходи за scope, не бери следующие таски «заодно».
3. Для harness-адаптеров: `tasks/research/harness-capability-matrix.md` —
   источник фактов о CLI; UNVERIFIED-пункты проверяются экспериментально
   при реализации, результат дописывается в матрицу.

## Правила реализации

- **Архитектура слоёв и запреты** — project-скилл
  `.agents/skills/glamor-architecture` (обязателен при любой работе с
  `backend/`): слои controller → service → repository, слой usecase
  ЗАПРЕЩЁН, controller не импортирует repository, self-DI запрещён.
- Кодстайл — D-80 (SALT): слои controller/service/repository,
  dto-пакеты, cstmerrors, ручной DI, gofumpt. Референс:
  `~/go/salt/dashboard-manager`.
- Миграции — D-05: goose v3 Go-файлами, `AddMigrationContext`, запуск
  при старте демона.
- Идемпотентность и журнал событий (D-10..D-16) — не опциональны: любой
  переход состояния — CAS-транзакция + событие в том же tx.
- Пайплайн никогда не делает `git commit`/`git push` (D-32).
- LLM только внутри этапов; ядро не вызывает модели.
- Тесты: acceptance-критерии таски = минимальный набор тестов. Юнит-тесты
  рядом с кодом; e2e с реальными harness'ами — под build tag `e2e`.
- Перед сдачей: `make build && make test && make lint` зелёные, diff
  перечитан, комментарии соответствуют поведению кода.

## Протокол статусов

- Начал таску → в её файле `Статус: in_progress` + дата.
- Закончил → `Статус: done` + секция «Итог» (что сделано, отклонения от
  таски со ссылками на обновлённый D-NN, как проверялось).
- Заблокирован → `Статус: blocked` + секция «Блокер» (что нужно от
  пользователя). Не выдумывать ответы за пользователя.

Граф зависимостей — в шапке каждой таски. Рекомендуемый порядок:

1. T-01 bootstrap → T-02 store (миграции, репозитории).
2. T-03 стейт-машина (ADR-001) → параллельно: T-04 (журнал/WS) и
   T-05 (OpenAPI/REST).
3. T-06 интерфейс harness → T-07 kimi → T-08 qwen.
4. T-09 supervisor → T-10 git → T-11 гейты → T-12 lifecycle демона.
5. T-17 дефолтный пайплайн (нужны T-03/T-07/T-11).
6. Фронт-трек (после T-05+T-04): T-13 → T-14, T-15, T-16 → T-18 Tauri.

M2+ таски (T-19..T-29) не начинать, пока M1 не зелёный целиком.
