## F-01: событие `run.created` в журнале (backend + фронт)

### Зачем

События `run.created` не существует: `runsapi.CreateRun`
(`backend/internal/service/runsapi/api.go:105-176`) не пишет в журнал,
`runsmachine` знает только `run.state_changed/stage.state_changed/gate.*`.
Фронт обходится REST-догоном неизвестного рана (`web/src/lib/dispatch.ts`,
`ensureRunKnown`), но ран в `draft` без переходов невидим для других
клиентов, а догон имеет гонку (чинится в fix-task-3, но с `run.created`
она станет несущественной). По духу D-11 (журнал — единый источник
истины) создание рана обязано быть событием.

### Что сделать

Backend:

1. `CreateRun` пишет событие `run.created` в журнал **в той же
   транзакции**, что и создание рана (как все переходы — D-11;
   `TxExecutor`/`EventAppender` уже в руках сервиса). Payload — объект
   рана целиком (как `gate.opened` несёт объект гейта): id, project_id,
   pipeline_version_id, task, branch, state, created_at — чтобы фронт
   мог построить карточку без REST.
2. Идемпотентность (D-12): повтор по `Idempotency-Key` возвращает
   существующий ран и НЕ должен писать второе событие `run.created`.
3. `api/openapi.yaml`: добавить `run.created` в EventKind/документацию
   payload-схем (по образцу существующих событий) → `make gen`.
4. Тесты: событие пишется и доезжает по WS/replay; повтор по ключу —
   событие одно; payload парсится фронтом (см. ниже).

Фронт:

5. `web/src/lib/dispatch.ts`: обработать `run.created` — upsert карточки
   из payload (без REST). `ensureRunKnown` оставить как fallback для
   любых неизвестных ранов (обратная совместимость: старые раны события
   `run.created` не имеют).
6. Обновить `lib/dispatch.test.ts`: `run.created` → карточка без fetch;
   неизвестный ран без `run.created` → прежний путь догона.

Опционально (если дёшево): TG-адаптер может использовать `run.created`
как точку создания «корневого» сообщения рана вместо текущей эвристики —
только если это упрощение, а не переписывание; иначе не трогать.

Документация: датированное дополнение в ADR-001 (событие создания рана)
и «Итог» T-05 (или релевантной таски).

## F-02: эндпоинт чтения артефакта + просмотр в UI

### Зачем

Табы «Промпт» и «Артефакты» показывают только метаданные
(`web/src/components/run/StagePanel.tsx:16-17,36` — явные заглушки):
в API нет чтения содержимого. Промпты сохраняются «для отладки» (T-17),
но смотреть их можно только через файловую систему.

### Что сделать

Backend:

1. `GET /runs/{runId}/artifacts/{artifactId}/content` (точную форму пути
   подбери по существующим маршрутам в `api/openapi.yaml` — сверься,
   как уже выглядят artifacts-эндпоинты; если список артефактов
   вложен в runs, контент тоже должен быть вложен).
2. Семантика: чтение файла артефакта с диска (артефакты лежат в
   `{run_dir}=~/.glamor/runs/<id>`, путь хранится в БД). Ответ:
   `text/plain; charset=utf-8` (или `application/octet-stream` +
   `Content-Disposition` для скачивания — выбери по простоте для фронта;
   фронту нужен текст).
3. **Безопасность обязательна**: путь файла брать ТОЛЬКО из записи БД по
   (run_id, artifact_id), никаких путей из query/пользователя;
   проверить, что resolved path остаётся внутри `run_dir` рана
   (filepath.Clean + prefix-проверка) — защита от скомпрометированной
   записи. 404 для чужого/несуществующего артефакта. Cap размера
   (например 5 МБ, как в TG-адаптере): больше — 413/пометка, фронт
   предложит «скачать» (или отдавать с Range — не надо, KISS).
4. Слои по скиллу: handler (контроллер) → service (каталог/artifacts —
   чтение записи из repo + чтение файла) → repository. Контроллер не
   читает repo сам.
5. openapi.yaml + `make gen`; хендлер вне strict-интерфейса не нужен,
   если oapi-codegen позволяет text-ответ — если нет, реализуй как
   кастомный handler на mux рядом (уже есть прецедент /ws) и задокументируй
   в спеке.
6. Тесты: 200 с содержимым; 404 чужой ран/несуществующий id;
   path traversal (запись с `../` в path — создать в тестовой БД) →
   404/400; файл больше cap → ожидаемый код.

Фронт:

7. Таб «Промпт»: клик по `prompt-<stage>-<iter>.md` → содержимое
   (моноширинный `<pre>` или Markdown-рендер — промпт это markdown,
   рендерь через существующий `components/Markdown.tsx`).
8. Таб «Артефакты»: просмотр содержимого по клику: `.md` — рендер,
   `.diff/.patch` — подсветка (моноширинный блок с раскраской +/- строк
   достаточно, без новых зависимостей), прочее — plain text. Больше cap —
   кнопка «скачать» (тот же URL с `download`-атрибутом).
9. Ошибки загрузки — видимая плашка, не молчаливый catch.
10. Убрать заглушки-пометки из `StagePanel.tsx`; дописать «Итог» T-14
    (датированное дополнение, ограничение про просмотр снять).
